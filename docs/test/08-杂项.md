# 8. 杂项（Misc，14 个模块）

> 本册只管 `src/main/java/dev/luminous/mod/modules/impl/misc/` 下的这 14 个：
> `AutoEZ` `AutoLog` `AutoReconnect` `Bot` `ChatAppend` `ExtraTab` `FakePlayer` `Friend`
> `KillEffect` `NoSound` `PacketLogger` `Punctuation` `Spammer` `Tips`。
> 环境准备、三档环境（L / S / C）、记录规范全在 [00-环境与工具](00-环境与工具.md)，这里不重复。
>
> **本册有 4 个模块是「测试工具」而不是产品功能**：`FakePlayer`（靶子）、`Bot`（自动脚本）、
> `PacketLogger`（抓包）、`NoSound`（静音对比）。先看 §8.2 把它们用熟，再回来测本册和其它册。

## 8.1 范围、档位与污染源

| 模块 | 干什么 | 档位 | 风险 |
|---|---|---|---|
| `FakePlayer` | 客户端假人，当靶子 | L | 低（但会吃你背包的图腾） |
| `Bot` | 12 模式的自动化脚本（交易/刷物品/挖沙） | S 自建服 | 高（公共服必封） |
| `PacketLogger` | 把发出的包打到聊天栏 | L / S | 低（刷屏、个别分支会 NPE） |
| `NoSound` | 按类别静音 | L | 低 |
| `Friend` | 一键把准星玩家加/移除好友 | L | 低 |
| `Tips` | 弹窗提示（死亡坐标/图腾/卡顿/药水） | L / S | 低 |
| `KillEffect` | 击杀处劈闪电 + 音效（纯客户端） | L | 低（`Trident` 音量极大） |
| `Punctuation` | 在准星命中的方块上打竖直标记 | L | 低 |
| `ChatAppend` | 每条聊天加后缀 | S（单机集成服即可） | 中：公共服禁言/踢 |
| `AutoEZ` | 有人死就自动嘲讽 | S（单机集成服即可） | 中：公共服禁言/踢 |
| `Spammer` | 定时刷屏 / 随机私聊 | S 自建服 | 高：公共服封号 |
| `AutoLog` | 危险时自动下线（发非法包让服务端踢你） | S | 高：会真的掉线 |
| `AutoReconnect` | 断线后自动重连 + 自动登录 | S | 中：明文密码落配置 |
| `ExtraTab` | 改 TAB 列表的行数/列数 | S（人多的服） | 中：TAB 渲染可能崩 |

**一句话判据**：本册除了 `AutoLog` / `AutoReconnect` / `Bot` / `ExtraTab`，其余都能在 **L 档（单机世界）** 跑完——
它们改的是客户端行为（假人、渲染、静音、提示）或客户端聊天（在单机集成服里发消息不打扰任何人）。

**测之前先确认这些是关的，否则你会把别人的问题记到这个模块头上：**

| 干扰源 | 会污染谁 | 为什么 |
|---|---|---|
| `Blink`（漏洞列） | `PacketLogger` | 它 cancel 掉包，日志里就看不到，看起来像"没发包" |
| `Velocity`（移动列） | `PacketLogger`、`FakePlayer` | 同上，且会吞掉击退包 |
| `Timer`（玩家列） | `Spammer`、`AutoReconnect`、`AutoLog` | 时间轴被加速，`Delay=5s` 实际不是 5 秒 |
| `NoSound` | `KillEffect`、`Punctuation`、`Tips` | 提示音被静音，你会以为模块没生效 |
| `ChatAppend` | `AutoEZ`、`Spammer` | 嘲讽句/广告后面会再多一个后缀，容易误判成"消息格式错" |
| `FakePlayer` 的 `AutoTotem` | `FakePlayer` 自己的死亡与图腾测试 | 它每 tick 补新图腾，假人打不死、图腾数也不减 —— 要测图腾必须先关掉它 |
| `Bot` 的 `AutoEat` | 你的食物 | 默认开，血/饱食度不够就吃附魔金苹果 |
| `AutoLog` | `AutoReconnect` | 一旦触发过，`loggedOut` 会拦住自动重连，直到你手动连进一次世界才复位 |

## 8.2 先学会这 4 个工具

### FakePlayer —— 战斗类测试的靶子

**怎么加 / 怎么删**

客户端命令前缀默认是 `;`（`ClientSetting → Misc → Prefix`）。`FakePlayerCommand` 只有三种用法：

| 命令 | 作用 |
|---|---|
| `;fakeplayer` | **不带参数 = 切换模块开关**。开 → 在你当前位置生成假人；再执行一次 → 关，假人被删除 |
| `;fakeplayer record` | 切换「录制我的走位」 |
| `;fakeplayer play` | 切换「假人回放录制的走位」 |

- **没有 `add` / `remove` 子命令**。别照旧版写 `-fakeplayer add`：本版加就是开模块，删就是关模块。
  也可以直接在 ClickGui → 杂项 → `FakePlayer` 点开关，效果一样。
- 假人生成后原地站着，不会跟着你。要挪位置就 **关→开**。
- 名字由 `Name` 决定（默认 `FakePlayer`），数组列表里显示的就是它。
- 在主菜单、还没进世界时开 → 模块自己 `disable()`（`nullCheck()` 拦住了）。

**服务端能看到它吗 —— 看不到**

- 它是 `mc.level.addEntity(...)` 加出来的纯客户端实体（`RemotePlayer` 子类），服务端既没有这个实体，也没有它的 `PlayerInfo`。
- 亲眼确认：进服后按 `TAB` 找不到 `FakePlayer`；第二个客户端看不见它；服务端 `/list` 里没有它。
- 后果：你对它挥的每一刀都会发一条 `ServerboundAttackPacket(它的 entityId)`，服务端查不到这个 id 直接忽略。
  所以它**只适合测客户端的选靶 / 转向 / 伤害数字 / 收包逻辑**；`AutoCrystal`、`Burrow`、`Surround` 这类
  「要服务端真交互」的模块，它帮不上忙（00 册 §0.3 也是这么说的）。

**能被打吗 —— 能，而且会掉血**

- 模块监听你发出的 `ServerboundAttackPacket`，命中它时自己算伤害、放 `PLAYER_HURT`、按 `Criticals` 的规则补暴击音和暴击粒子。
- 但**打不死是常态**：`AutoTotem`（默认**开**）每 tick 把主手、副手都补成图腾，吃掉一个立刻再发一个新的。
- 血到 0 之后它**不会消失、也不播死亡动画**，只是 `isAlive()` 变 false → Aura 这一类不能再选它。想复位：关→开。

**图腾判定（本册风险点，26.2 改过）**

- 26.2 把 `LivingEntity#tryUseTotem` 变成 private 的 `checkTotemDeathProtection`，模块通过 `@Invoker`
  （`ILivingEntity#alienClient$checkTotemDeathProtection`）调用。这条链路坏了，表现是「打死了但图腾不触发」。
- 测法（**必须先关 `AutoTotem`**）：`AutoTotem` 关 → 你自己副手放 3 个图腾（`/give @s minecraft:totem_of_undying 3`）
  → 一直打假人 → 第 1、2、3 次死都吃图腾、血回到 10，第 4 次真死。
- **图腾数会真的减少，而且减的是你自己那一格**：假人的背包是 `getInventory().replaceWith(player.getInventory())`
  复制的，`ItemStack` 是**同一个对象**，它 `consume` 掉一个，你副手那格的数字就少 1。别拿唯一的一叠测。
- 每次吃图腾都会 `Alien.POP.onTotemPop(fakePlayer)` → `Tips/PopCounter` 会喊 `FakePlayer popped N totems.`
  （非自己时源码恒用复数）。注意源码是**先记账再吃图腾**，所以「图腾已经吃完还继续被打死」时计数照样 +1，这是预期，不是 bug。

**水里 / 岩浆里的摆动（本册风险点，26.2 改过）**

- 26.2 用 `IWalkAnimationState`（`@Accessor`）搬 `walkAnimation.position`（步态相位），并复制 `leaningPitch`、
  `wasTouchingWater`、`Pose`。这条链路坏了，表现是「水里的假人像根柱子」或四肢相位乱跳。
- 测法：**先自己**站进水里游两下（让倾角/相位非 0）→ 再 `;fakeplayer` → 假人应是涉水/游泳姿态，不是直立方块人；
  换岩浆重来一次（`wasTouchingWater` 只处理水，岩浆里应当是「直立 + 着火」，不要期待它也会游泳）。
- 姿态只在**生成那一刻**复制一次。你先开假人、自己再进水，假人看着不斜 —— 这是设计，别记 bug。

**record / play**

- `;fakeplayer record` 开 → 走一圈 → 再执行一次关（`Record` 关时不清列表，重新开才会清）→ `;fakeplayer play` 开 → 假人沿路线走。
- 回放用 `snapTo`（26.2 客户端没有 `updateTrackedPosition`），所以是**跳格**移动，不是平滑动画。

**Damage（默认开）**：收到爆炸包时按 `AutoCrystal.calculateDamage` / `AutoAnchor.getAnchorDamage` 给假人扣血，
只算 10 格内。关掉 → 旁边炸个真水晶，假人纹丝不动。

### Bot —— 12 个模式的自动化脚本，**不是**"会自动打你的假人"

先把话说清楚，否则你会找错工具：

- 源码里 `Bot` 的 `Mode` 有 12 个：`AutoTrade`（默认）、`ItemFrameDupe`、`XinDupe`、`NPlusOneDupe`、
  `TridentDupe`、`TurtlePath`、`Turtle`、`SandMiner`、`ScoreFarmer`、`SlabPlacer`、`Ominous`、`None`。
- 它**不会攻击你、也不会追着你打**。00 册里「Bot 会自动打你，适合测 `AutoTrap`/`Surround` 防守」这句在本版**不成立**。
  测防守类请用**真第二个玩家**（`Tester2` 双开）或 `FakePlayer` + 手动砍你。
- 本版 Bot 唯一「打人」的地方是 `XinDupe` 的 `Kill` 阶段杀**自己的羊驼**（`mc.gameMode.attack`），目标不是玩家。
- 12 个模式里除了 `AutoTrade` / `Turtle` / `SlabPlacer` / `Ominous`，其余都是复制、刷物品、自动挖沙这类脚本
  （`XinDupe` 羊驼刷潜影盒、`TridentDupe` 三叉戟、`ItemFrameDupe` 展示框、`NPlusOneDupe` 1+n）
  → **只在自建服开**，公共服等于自封号。

**本册风险点：剑判定改成 `ItemTags.SWORDS`**

- 26.2 的 `SwordItem` 类被扁平化（剑 = 普通 `Item` + 武器组件 + 标签），源码里两处从
  `InventoryUtil.findClass(SwordItem.class)` 改成 `InventoryUtil.findTag(ItemTags.SWORDS)`：
  `SandMiner`（`Aura` 有目标时切剑）和 `XinDupe` 的 `Kill` 阶段。
- **坑**：`findTag` 只扫**快捷栏 0–8**（`findTagInventorySlot` 才是全背包 36 格）。剑在主背包里时返回 `-1`，
  然后照样 `switchToSlot(-1)` —— 手会变空、还会发一个 `-1` 号槽的包。
- 测法：`Mode=SandMiner`，快捷栏放剑 → 开 `Aura` 锁住一个假人 → Bot 应切到剑所在格、并取消 Baritone；
  再把剑挪到背包第 2 页 → 看是不是切到 `-1`（这是要盯的回归点）。
- `XinDupe` 那条链路要羊驼 + 箱子 + 鸡蛋 + 干草块，太重，只在自建服上顺手验。

**测 Bot 任何模式前先关 `AutoEat`**（默认开，`Hunger`=10、`Health`=20）：血 < 20 或饱食度 < 10 就吃
附魔金苹果 / 金苹果 / 金胡萝卜；`AnyFood` 打开会吃任何食物。你测别的东西时背包会被他吃空。

### PacketLogger —— 看模块到底发了什么包

**输出到哪（先记住：它不是文件日志）**

- 它走 `CommandManager.sendMessage` → **客户端聊天栏**，一行一个包，刷得极快。
- 落盘位置：`.minecraft/logs/latest.log`（开发环境是 `run/logs/latest.log`），客户端系统消息会以
  `[CHAT] ...` 行写进去。默认通知样式 `Mio` 走的是自定义 hook，不保证落盘；
  想稳定留档就把 `ClientSetting → Notification → Style` 切到 `Earth` 或 `Moon`（走原版 `addClientSystemMessage`，一定进 `latest.log`）。
- 怕消息被顶掉：把 `ClientSetting → ChatHud → InfiniteChat` 打开，或直接 `F2` 截图。

**格式长什么样**（下面是源码里真实的字符串，`%s`/`%d` 是实际值）

| 开关 | 打印 |
|---|---|
| `MoveFull` | `PlayerMove Full - x: 12.3, y: 64.0, z: -8.7 yaw: 90.0, pitch: 0.0  onground: true` |
| `MovePosition` | `PlayerMove PosGround - x: 12.3, y: 64.0, z: -8.7  onground: true` |
| `MoveLook` | `PlayerMove LookGround - yaw: 90.0, pitch: 0.0  onground: true` |
| `MoveGround` | `PlayerMove Ground - onground: true` |
| `InteractEntity` | `InteractEntity - Entity: FakePlayer, id: 1234` ← **26.2 的攻击包也记在这一项** |
| `InteractBlock` | `InteractBlock - pos: 1, 64, 2, dir: UP, hand: MAIN_HAND` |
| `InteractItem` | `InteractItem - hand: MAIN_HAND` |
| `ClickSlot` | `ClickSlot - type: SWAP, slot: 36, button: 0, id: 0` |
| `PickInventory` | `PickFromInventory - slot: 36, to hotbar/offhand: 0` |
| `PlayerAction` | `PlayerAction - action: START_DESTROY_BLOCK, direction: UP, pos: 1, 64, 2` |
| `S2cVelocity` | `S2C Velocity, x: 0.0, y: 0.0, z: 0.0, isExplosion: true` |
| `TeleportConfirm` | `TeleportConfirm - id: 5` |
| `ClientCommand` | `ClientCommand - mode: START_SPRINTING` |
| `VehicleMove` / `UpdateSlot` / `HandSwing` / `Pong` / `CloseScreen` / `ClientStatus` | 同风格一行 |

**怎么用它验证 `Aura` 有没有发 `ServerboundAttackPacket`**（本册最重要的用法）

1. 把除 `InteractEntity` 之外的开关**全关**（26.2 的攻击包就记在 `InteractEntity` 这一项下面，虽然名字不像）。
2. 生成一个假人（或站到真玩家 3 格内），开 `Aura`。
3. 每砍一次，聊天栏应该出现一行：`InteractEntity - Entity: FakePlayer, id: <假人的 id>`，id 每次都是同一个。
4. 判读：
   - **有这行 + id 正确** → 包真的发了；
   - **没有这行** → 没发包，或包被别的模块吃了（见下一条）；
   - **有这行但目标不掉血** → 包发了服务端不认（打的是假人 / 距离超了 / 反作弊拦了）。

**为什么它能当「到底发没发包」的判据**

- 它挂在发包事件的**最低优先级**（`priority = -999999`），而事件总线在 `event.cancel()` 之后会**停止派发**。
- 所以：**日志里有 = 包真的出去了；日志里没有 ≠ 模块没执行**（可能是被 `Blink` / `Velocity` 拦了）。
  排查时先单独关掉 `Blink`、`Velocity` 再复测。

**「模块开了没反应」通用排查流程**

1. 打开 PacketLogger，只留你要看的那一类开关；
2. 开要测的模块，做一个动作；
3. 对照「应该出现的包」：

| 模块 | 应该看到 |
|---|---|
| `Surround` / `AutoTrap` / `Burrow`（战斗） | `InteractBlock` |
| `Offhand` / `AutoRegear`（战斗） | `ClickSlot - type: SWAP` |
| `AutoMend`（战斗） | `InteractItem - hand: MAIN_HAND` |
| `Aura`（战斗） | `InteractEntity`（id = 目标） |
| `Criticals`（战斗） | `PlayerMove Full/PosGround` 紧贴着 `InteractEntity` |
| `Velocity`（移动） | 生效时你自己的 `PlayerMove Full` 被压制一段时间；还在正常发 = 只改了本地速度 |

4. 一条都没有 → 模块根本没走到发包那一步，回去看 `latest.log` 里 `[Alien]` 附近。

**坑**

- 19 项默认全开，刷屏 + 掉帧。测一项只留一项。
- `InteractEntity` 分支对「查不到的实体」没有判空（`Criticals.getEntity(packet).getName()`）→
  攻击一个刚死、刚卸载的实体，聊天栏会抛 `NullPointerException`。看到就把 `InteractEntity` 关掉，别当模块崩了。
- 它只读不改：日志里有包 ≠ 服务端接受。

### NoSound —— 判断"这个声音是谁放的"

- 7 项开关（`ArmorEquip` `Explode` `Attack` `Teleport` `Throw` `Potion` `Elytra`），默认全开。
- 它 hook 的是客户端播放声音的入口（`PlaySoundEvent`）：**原版下发的音效和模块自己 `mc.level.playSound` 的，都经过它**。
- 用法 1（本册）：想确认某个声音是哪一类 → 把对应项单开 → 声音消失 = 属于这一类；还在 = 匹配不上（不在列表里）。
- 用法 2（别的册）：测 `KillEffect` / `Punctuation` / `Tips` 的提示音前，先确认 `NoSound` 没把对应项开着，
  否则你会把「被静音」记成「模块没生效」。
- 26.2 实现变了：`SoundEvent` 变成 record，判定改成比较 `SoundInstance#getIdentifier()` 与 `SoundEvent#location()`。
  所以「某一项完全不生效」多半是 **Identifier 不匹配**（例如 `Explode` 只匹配 `GENERIC_EXPLODE` 和
  `DRAGON_FIREBALL_EXPLODE`，TNT/苦力怕的爆炸声标识不同，仍会响）→ 记 ⚠️，别记 ❌。
- 它**不**包含 `PLAYER_LEVELUP`（KillEffect）、`TRIDENT_THUNDER`（KillEffect 的 `Trident`）、
  `EXPERIENCE_ORB_PICKUP`（Punctuation / Tips）→ 这些提示音 NoSound 全开也照样响。

## 8.3 会往服务器聊天里写字的模块（红线）

**只有 3 个**：`AutoEZ`、`ChatAppend`、`Spammer`。它们走的是真正的 `sendChat` / `sendCommand`，服务端、反作弊、管理员全都看得见。
（`Punctuation` **不是**发消息类：旧版的坐标广播/BASE64/加密上传已经删掉，现在只做本地标记，见 §8.5。）

| 模块 | 往哪写 | 公共服的后果 | 安全的测法 |
|---|---|---|---|
| `ChatAppend` | 你**每一条**聊天后面加后缀 | 明显外挂特征 → 禁言 / 踢 / 记录 | **单机世界**（集成服）里发 `hi` 就能验 |
| `AutoEZ` | 有人死就发嘲讽句 | 刷屏 + 挑衅 → 禁言 / 封 | **单机世界**里用 `FakePlayer` 当死者，或 `/kill` 自己 |
| `Spammer` | 每 `Delay` 秒刷一句 / 随机私聊 | 直接封号 | **自建 Fabric 服**（`00` 册 §0.3 那个），`Message` 改 `test`、`Delay` 1 秒 |

**单机怎么测**：直接进单机世界就行——集成服本身就是服务端，聊天、死亡、断线都走真协议，而且不会打扰任何人。
需要「第二个人」时再 `Esc → 对局域网开放 → 允许作弊：开`，或用 `FakePlayer` 顶替。

**三条纪律**

1. 别在公共服开这三个，尤其别在带屏录/直播的号上。
2. 测 `AutoEZ` 前把 `Range` 调小（默认 10），`Range=0` 是**全场无限制**——服里任何一个人死都会嘲讽。
3. 测完**立刻关掉**，别留在配置里（配置会在下次启动自动加载，你会在某个服里"莫名其妙"被禁言）。

## 8.4 建议测试顺序

先工具、再纯客户端、最后「会掉线、会刷物品」的：

| # | 模块 | 风险 | 为什么排在这 |
|---:|---|---|---|
| 1 | `FakePlayer` | 低 | 后面好几个模块的靶子，先确认它能生成/能挨打 |
| 2 | `PacketLogger` | 低 | 后面判断「有没有发包」全靠它 |
| 3 | `NoSound` | 低 | 顺便确认你听得见提示音，别把静音当失效 |
