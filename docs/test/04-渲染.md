# 4. 渲染 Render（13 个）

> 本册管 `src/main/java/dev/luminous/mod/modules/impl/render/` 里**信息可视化**类的 13 个模块（框、线、字、模型叠加、粒子）。
> **GUI 里没有单独的「渲染」列** —— ClickGui 是 1.21.1 的 7 列原始布局，这 13 个和 05 册那 11 个**都在 `Render` 列（共 24 个）**，本册只是按功能拆出来便于一次只测一类。
> 环境准备、记录规范在 [00-环境与工具](00-环境与工具.md)，这里不重复。
> 视觉改造类（`Shader` / `NoRender` / `Xray` / `Ambience` / `Fov` / 镜头）在 [05-视觉](05-视觉.md)，**同一列、同一目录，别找错册**。

## 4.1 适用范围

**覆盖**：把「实体/方块/坑/放置/挖掘/下线点」这些**信息**画到画面上——框、线、字、模型叠加、粒子。

| 主题 | 模块 |
|---|---|
| 实体/方块框 | `ESP` `HighLight` `HoleESP` `PhaseESP` `PlaceRender` `BreakESP` `LogoutSpots` |
| 模型叠加 | `Chams` `PopChams` |
| 文字 / 线 / 轨迹 | `NameTags` `Tracers` `Trajectories` |
| 粒子 | `TotemParticle` |

**不覆盖**：`Shader` / `NoRender` / `Xray` / `Ambience` / `Fov` / `AspectRatio` / `CameraClip` / `Crosshair` / `MotionCamera` / `ViewModel` / `Zoom`（同样在 `render/` 目录，但属 `Category.Visual`，见 05 册）。

**环境**：默认 **L（单机创造）**。三个例外：`NameTags`、`LogoutSpots`、`BreakESP` 需要**真实第二个玩家**——单机存档「对局域网开放」后用小号进，或用 `Misc/FakePlayer`（假人够验显示、不够验上下线）。

**交叉污染（测之前先确认这些是关的）**：

| 干扰源 | 会污染谁 |
|---|---|
| `Shader`（05 册） | **所有**渲染模块。它把选中实体塞进原版发光描边并接管 `doEntityOutline` 的合成，你看到的"描边"可能不是 `ESP`/`Chams` 画的 |
| `NoRender`（05 册） | `ESP`/`NameTags`/`TotemParticle`：`Invisible`、`Items`、`Effect` 会直接把目标实体/粒子掐掉 |
| `Xray`（05 册） | `HighLight`/`PhaseESP`：方块渲染被砍掉一半，"框对不上方块"多半是它 |
| `Ambience`（05 册） | `Chams`/`PopChams`/`Trajectories`：`FullBright`/`WorldColor` 会改 lightmap，颜色看着不对 |
| `NameTags` × `LogoutSpots` | 两个都在头顶画字，会重叠 |
| `ESP` × `Chams` × `Shader` | 都会改同一批实体的 RenderType / 描边状态 |

## 4.2 测试场地建议

**超平坦 + 一道墙 + 几个靶子**。别在自然地形测：草、水、树叶会吃掉"框贴不贴合"的判断。

```mcfunction
# 进服先变创造（下面全部相对脚下）
/gamemode creative

# A. 33×33 石台，方便看远处框是否贴合
/fill ~-16 ~-1 ~-16 ~16 ~-1 ~16 minecraft:stone

# B. 3 格厚的墙（东西向 9 长、5 高、3 厚）—— 测「穿墙 / 被遮挡」
/fill ~4 ~ ~-4 ~6 ~5 ~4 minecraft:stone

# C. 2 个 1×1、深 2 的坑 —— HoleESP / PhaseESP 共用
/fill ~-8 ~-2 ~-8 ~-8 ~-1 ~-8 minecraft:air
/fill ~-6 ~-2 ~-8 ~-6 ~-1 ~-8 minecraft:air

# D. 靶子：一个生物、一个水晶、一个村民、一头牛、一个僵尸
/summon minecraft:villager ~-3 ~ ~2
/summon minecraft:cow ~-3 ~ ~5
/summon minecraft:zombie ~3 ~ ~2
/summon minecraft:end_crystal ~4 ~ ~-2

# E. 方块实体靶子：箱子 / 末影箱 / 潜影盒
/setblock ~ ~ ~6 minecraft:chest
/setblock ~2 ~ ~6 minecraft:ender_chest
/setblock ~4 ~ ~6 minecraft:shulker_box

# F. 掉落物：丢 3 组（其中一组数量  1，用来验 Count）
/give @s minecraft:diamond 3
/give @s minecraft:iron_ingot 16
```

**第二个玩家**：LAN 开放后用小号 `Tester2` 进，站到墙的另一侧。`NameTags`/`LogoutSpots` 没有第二个人基本测不了。

**记录**：动手前 `F3` 抄下坐标，每节测完 `/tp` 回原点。**一次只开一个模块**（见 4.4）。

| 3 | `HoleESP` | 颜色分类 + 距离淡出，像看图例 |

| 8 | `Trajectories` | 要拉弓、要对墙，步骤多 |

## 4.4 本册特有陷阱

**① 渲染类问题经常不是模块坏了，是被别的模块覆盖。**
26.2 有好几个模块会改**同一批实体**的 RenderType / 描边 / 深度状态：`Shader`（把实体塞进发光描边并接管合成）、`Chams`（水晶整个 `submit` 被 cancel 后自己重画）、`ESP`/`Tracers`（同一个 gizmo 收集器）。
两个模块都改同一个实体时，后提交的会盖掉前面的，**看起来就像其中一个"开了没反应"**。
→ 每节开始前，把除被测模块以外的渲染/视觉模块**全部关掉**（`ClickGui → 渲染/视觉` 两列全灭），只留 `HUD`（或干脆连 `HUD` 也关）。

**② 截图前按 `F1`，不然 HUD 挡住判断。**
`HUD`、数组列表、水印、药水图标、聊天栏都会压在你正在看的框/字上。按 `F1` 全部隐藏。
`NameTags` 是例外里的例外：它挂在 `Hud#extractRenderState` 的 **TAIL**，按 `F1` **仍然会画**，所以验名牌时 `F1` 是安全的。
（`Crosshair` 相反：它画在 `extractCrosshair` 里，`F1` 会一起藏掉，见 05 册。）

**③ 画面没变化，先按 `F3+T` 重载资源。**
26.2 的后处理链（`Shader` 的 7 条 + ClickGui 的 `alien:blurarea`）、模型/图集缓存、区块渲染数据，全都在资源重载后重建。
`Xray` 与 `Ambience → CustomLuminance` 还会主动调 `levelExtractor.allChanged()` 重建区块——所以这两个模块**开关时画面会闪一下**，是重算，不是崩。

**④ gizmo 管线是「提交 → 下一帧定型」，天生慢一帧。**
26.2 把世界几何改成提交节点模型（`Gizmos.addGizmo`），`LevelRenderer` 在下一帧 extract 阶段才合批绘制。所以快速转视角时，框可能比画面**慢半帧到一帧**——这是实现差异，不是错位。
判据要卡住：**站着不动时框必须严丝合缝；只有"固定偏一格/一直偏左"才算 bug。**

**⑤ 大多数框是「永远穿墙」的。**
`Render3DUtil` 提交的 gizmo 默认带 `setAlwaysOnTop()`（= 旧的关深度测试），所以 `ESP`/`Tracers`/`HoleESP`/`PhaseESP`/`Trajectories` 的框在墙后也可见——**这是设计，不是"深度失效"**。
本册里唯一能验「被方块正常遮挡」的是 `Chams → Custom → Depth` 和 `HighLight → Depth`（这两个是真深度开关）。

`render/ESP.java` · 环境：**L** · 风险：低

| 项 | 内容 |
|---|---|
| 前置 | 场地 A~F 就位；一个玩家/假人、掉落物若干、箱子/末影箱/潜影盒各一个、末地传送门方块（`/setblock ~ ~ ~ minecraft:end_portal`）；只开 `ESP` |
| 关键设置 | `BoxESP`（总开关，默认开）→ 颜色组：`ItemFill`/`ItemOutline`（开）、`PlayerFill`/`PlayerOutline`（开）、`ChestFill`/`ChestOutline`（**关**）、`EnderChestFill`/`EnderChestOutline`（**关**）、`ShulkerBoxFill`/`ShulkerBoxOutline`（**关**）、`EndPortalFill`/`EndPortalOutline`（**关**）<br `ItemName`（默认**关**）→ `CustomName`（关）、`Count`（开）、`Text`（颜色）<br `PearlOwner`（开） |
| 步骤 | 1. `BoxESP` 开着，看地上的掉落物和玩家身上是否出现框<br 2. 打开 `ItemName`：物品上方应出现名字，数量  1 的后面带 ` x16`<br 3. 站到 20 格外再走回来，盯住框是否**贴着实体碰撞箱**、有没有固定偏移<br 4. 原地左右转 90°，看框是否跟着转、有没有残留（错位/拖影）<br 5. 依次打开 `ChestFill`/`EnderChestFill`/`ShulkerBoxFill`，看三个箱子各自上色<br 6. 丢一颗末影珍珠，`PearlOwner` 开着时珍珠上方应出现最近玩家（或投掷者）的名字<br 7. 用铁砧给一组物品改个自定义名，对比 `CustomName` 开/关时的文字 |
| 预期 | 框严格贴合实体碰撞箱（玩家框比身体略高是 `inflate(0,0.1,0)` 的固有偏移）；`ItemName` 关时**不出现**任何文字；每个颜色项的开关**即时**增删对应框；珍珠显示投掷者名字 |
| 失败信号 | 框偏一格或粘在原地（gizmo 用了过期坐标）/ 所有框同一个颜色（颜色项接错）/ 箱子类怎么开都不画（`BlockUtil.getTileEntities` 取不到方块实体）/ 文字不显示或糊成一团（`TextGizmo` 世界缩放 0.32 基准）/ 名字不随距离变化大小（那是 `NameTags` 的事，`ESP` 的文字是世界空间固定大小） |
| 结果 | [ ] ✅　[ ] ⚠️　[ ] ❌ |

> 26.2 细节：`ItemName` 是**独立开关**（别和 `BoxESP` 合并成一个"物品透视"）；名字走 `TextGizmo` 提交（世界空间），**不会**像屏幕文字那样恒定大小。

### HoleESP（坑透视）
`render/HoleESP.java` · 环境：**L** · 风险：低

| 项 | 内容 |
|---|---|
| 前置 | 场地 C 的 1×1×2 坑；另外搭三个坑：①四面黑曜石 + 底黑曜石（基岩坑的替代）②一面石头三面黑曜石（半安全）③只有 1 格高的凹坑（空气坑） |

| 预期 | 三种坑三种颜色（基岩=绿 / 普通=红 / 空气=单独色）；随距离淡出；`Height` 控制框高度；走远后框**最终消失** |
| 失败信号 | 全是同一个颜色（把 `Safe` 当成"安全=普通坑"——**反了**：`Safe`=基岩坑）/ 走远后框一直不消失（`UpdateDelay` 过大，或线程列表没清）/ 框比坑大一圈/小一圈（`Height`、`AirHeight`、`WallHeight` 三个高度项用混）/ 一开就狂刷扫描（`Distance` 20 时 `getSphere` 半径很大） |
| 结果 | [ ] ✅　[ ] ⚠️　[ ] ❌ |

> 26.2 细节：坑的扫描跑在**独立线程**（`onThread`），主线程只负责画。所以 `UpdateDelay` 调大时你会看到"框在旧位置停一会儿"，属正常。

| 项 | 内容 |
|---|---|
| 前置 | 第二个玩家（或假人）穿一整套带附魔的甲、主手拿剑、副手拿盾；主客户端第一人称 |

| 结果 | [ ] ✅　[ ] ⚠️　[ ] ❌ |

> 26.2 关键变化：`NameTags` 从「世界空间即时模式广告牌」改成 **GUI 层绘制**（`GuiGraphicsExtractor` + `worldSpaceToScreenSpace` 投影 + `pose().scale()`）。
> 要验的就是三件事：**① 头顶位置跟不跟得上人物移动 ② 远近缩放正不正常 ③ 名字/血量/装备图标是不是都画出来了**。
> `ShowDistance` 是 26.2 新加的项，默认关，老配置里没有它也不会丢别的值。

## 4.6 本册回归优先级（20 分钟版）

时间不够时只跑这 4 个，它们卡住「gizmo 世界几何 / 后处理合成 / 方块渲染管线 / GUI 投影」四条 26.2 高风险链路：

| 顺序 | 模块 | 时长 | 只测这一件事 |
|---|---|---:|---|
| 1 | `ESP` | 5 min | 掉落物+玩家+箱子的框**严丝合缝**、转头不错位、`ItemName` 打开有字 |
| 2 | `NoRender`（05 册） | 5 min | `Fog` / `Blindness` / `Darkness` / `Fireworks` 四个 26.2 新实现子项各开关一次，画面必须真的变 |
| 3 | `Xray`（05 册） | 5 min | 开→石头消失只剩矿；`Edit` 里取消一种矿→该矿立刻消失；关→地形恢复 |
| 4 | `NameTags` | 5 min | 第二个人横移时名牌**跟得上**；近大远小；名字+血量+6 格装备图标都在 |

> 这 4 个全过，本册可按「基本可用」放行；剩下 11 个（`Tracers`/`HoleESP`/`Chams`/`PopChams`/`TotemParticle`/`Trajectories`/`HighLight`/`PlaceRender`/`PhaseESP`/`BreakESP`/`LogoutSpots`）按 4.3 的顺序补。
> 只测 04 册不测 05 册的话，`Shader` 与 `NoRender` 这两条最可能翻车的链路等于没验——它们改的是**整帧合成**，坏了是"一片黑/一片发光"，不是单个框的问题。
