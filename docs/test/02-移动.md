# 2. 移动（Movement，22 个模块）

> ClickGui 第 2 列「移动」的全部 22 个模块，源码目录 `src/main/java/dev/luminous/mod/modules/impl/movement/`。
> 全册统一 **S 环境**：进服（单机「对局域网开放」也算）。原因很简单——移动模块的好坏 = **服务端是否接受你的位置**，
> 单机集成服会把很多本该拒绝的动作放过，于是「单机通过」说明不了任何事。

## 适用范围

**覆盖**：水平速度、垂直位移、飞行、搭路与边缘保护、输入同步、反击退。

| 主题 | 模块 |
|---|---|
| 水平速度 | `Speed` `Strafe` `BlockStrafe` `Sprint` `NoSlow` |
| 垂直 / 飞行 | `Fly` `PacketFly` `ElytraFly` `VClip` `AntiVoid` `FastFall` `Step` `FastSwim` `FastWeb` |
| 搭路 / 边缘 | `Scaffold` `SafeWalk` `HoleSnap` `AutoWalk` |
| 输入 / 同步 / 击退 | `MovementSync` `NoJumpDelay` `EntityControl` `Velocity` |

**不覆盖**：`NoFall`、`Timer`、`Freecam`（在 `03-玩家.md`）；`Surround` / `Burrow` 自带的位移（在 `01-战斗.md`）。

**交叉污染**（测之前先确认这些是关的，否则你会把别人的问题记到这个模块头上）：

| 干扰源 | 会污染谁 |
|---|---|
| `Timer`（玩家列） | `FastFall` `FastWeb` `Speed` `Step` —— 全部都是时间轴 |
| `NoFall`（玩家列） | 任何「从高处落下」的测试 |
| `Blink`（漏洞列） | 所有位移，它会把发包延后，看起来像"开了没反应" |
| `MovementSync` | 所有带旋转的模块（`Scaffold` / `HoleSnap` Grim / 战斗类），它会把"侧着走"变成"真的转身" |
| `Fly` / `PacketFly` | `FastFall` 直接 `Fly.INSTANCE.isOn()` 就 return，两个别同开 |

## 测试场地建议

**超平坦世界 + `/tp` 记录起点**。别在自然地形测移动——坡、水、草会吃掉现象。

```mcfunction
# 进服后先把自己变成创造，拿齐道具
/gamemode creative
/give @s minecraft:obsidian 256
/give @s minecraft:elytra
/give @s minecraft:firework_rocket 64
/give @s minecraft:cobweb 64
/give @s minecraft:water_bucket
```

站到平坦地面的中心，**面朝 +X（东）**，然后依次执行（全部相对你脚下，不用改数字）：

```mcfunction
# A. 40 格直线跑道 —— 量水平速度（Speed / Strafe / Sprint）
#    用 smooth_stone 是为了和地面 stone 区分，一眼能看出跑道到哪
/fill ~ ~-1 ~ ~40 ~-1 ~ minecraft:smooth_stone

# B. 1 格台阶 / 2 格台阶 —— Step（往 +Z 走、不按空格）
/setblock ~ ~ ~2 minecraft:stone
/fill ~ ~ ~6 ~ ~1 ~6 minecraft:stone

# C. 蜘蛛网柱 1×1×3 —— FastWeb
/fill ~2 ~ ~-2 ~2 ~2 ~-2 minecraft:cobweb

# D. 3×3×2 水池 —— FastSwim
/fill ~4 ~-2 ~-2 ~6 ~-1 ~0 minecraft:air
/fill ~4 ~-2 ~-2 ~6 ~-1 ~0 minecraft:water

# E. 标准 1×1 坑（深 2、四面硬墙）—— HoleSnap
/fill ~-1 ~-1 ~8 ~1 ~-1 ~10 minecraft:obsidian
/setblock ~ ~-1 ~9 minecraft:air
/setblock ~ ~ ~9 minecraft:air
/fill ~-1 ~-1 ~8 ~-1 ~ ~10 minecraft:obsidian
/fill ~1 ~-1 ~8 ~1 ~ ~10 minecraft:obsidian
/fill ~-1 ~-1 ~8 ~1 ~ ~8 minecraft:obsidian
/fill ~-1 ~-1 ~10 ~1 ~ ~10 minecraft:obsidian

# F. 20 格高的悬空平台 —— FastFall / Fly / ElytraFly 起跳点
/fill ~-2 ~20 ~4 ~2 ~20 ~8 minecraft:stone
```

**记录起点**：动手前按 F3 抄下脚下方块坐标，每测完一个模块 `/tp @s <x> <y> <z>` 回来（或用 `F3+C` 复制坐标）。
后面所有「位移几格」「速度变快」都靠这个点做基准，别凭眼睛估。

**`allow-flight=true` 必须先改**（`server.properties`），否则 `Fly` / `PacketFly` / `ElytraFly` 会被服务端
以 `Flying is not enabled on this server` 直接踢，你会误判成模块坏了。

## 建议顺序（低危 → 高危）

1. `NoJumpDelay`　2. `AutoWalk`　3. `Sprint`　4. `Strafe`　5. `SafeWalk`
6. `AntiVoid`　7. `FastSwim`　8. `FastWeb`　9. `EntityControl`　10. `FastFall`
11. `MovementSync`（先把它测明白，后面所有旋转相关的判断都依赖它的开/关状态）
12. `NoSlow`　13. `BlockStrafe`　14. `Step`　15. `Velocity`　16. `Fly`　17. `HoleSnap`　18. `Scaffold`
19. `Speed`　20. `ElytraFly`　21. `PacketFly`　22. `VClip`

> 最后四个是「最容易被服务端踢 / 最容易被反作弊判死」的，放最后测：万一前面已经把号搞进观察名单，
> 至少前面 18 个的结果还是干净的。另外 `ElytraFly` 的「松手」验证需要**第二个玩家**（或第二个客户端）在场，
> 提前把双开准备好。

### FastFall（快速坠落）
`movement/FastFall.java` · 环境：**S** · 风险：中

| 项 | 内容 |
|---|---|
| 前置 | 20 格以上落差（场地 F）；确认 `Timer`（玩家列）是关的，否则分不清是谁在加速 |
| 关键设置 | `Mode`（默认 `Fast`，可选 `Fast` / `None`）、`NoLag`（true）、`UseTimer`（false）→ `Timer`（2.5）、`Anchor`（true）、`Height`（10） |
| 步骤 | 1. 关模块从 F 平台跳下，记落地时间（秒表）<br>2. 只开模块（`UseTimer=false`）：再跳一次，下落时间应**没有**变化（默认不动时间轴），只有贴地手感变"沉"<br>3. 打开 `UseTimer` + `Timer=2.5`：再跳，下落明显变快，时间约为原来的 40%<br>4. `Anchor` 验证：站到平台边缘，让身体一半探出（脚下中心是空气、下方 10 格内有地面）再关/开 `Anchor`，对比横向挪动的距离——开时应被压到 5%，几乎挪不动<br>5. `Height` 10→3：同样的边缘位置，下方 4~10 格才有地面时 `Anchor` 不再触发<br>6. `NoLag` 关掉：贴地压制从 0.62 变成 1.0，肉眼几乎无差别，只记一行观察 |
| 预期 | `UseTimer` 打开后下落时间缩短到约 40%；`Anchor` 生效时贴边几乎无法横向移动；`Height` 决定这个"下方多少格内算有地面" |
| 失败信号 | 完全没感觉（`UseTimer` 没开）/ 下落速度忽快忽慢 / 被踢（`Timer` 别超过 4） |
| 结果 | [ ] ✅　[ ] ⚠️　[ ] ❌ |

> 它其实是两个互不相干的功能拼在一起的：**`UseTimer` 管"掉得快"**（时间轴加速），
> **`Anchor` 管"落地瞬间横向别滑出去"**（水平速度 ×0.05）。默认 `UseTimer=false`，
> 所以"开了没感觉"是正常的——先打开 `UseTimer` 再判断这个模块死没死。

### MovementSync（移动同步）
`movement/MovementSync.java` · 环境：**S** · 风险：中

| 项 | 内容 |
|---|---|
| 前置 | 先记下 `AntiCheat` 模块里与它无关的开关状态；`HoleSnap` 的 `Grim` 模式**依赖它** |
| 关键设置 | 无设置项。开启后 `AntiCheat.movementSync()` 为真，旋转发包前会按移动向量重算 `Input` |

> 判定方法：第二个玩家站在你侧面，盯你的潜行姿势 + 鞘翅开合（1.5 格高的缝也能验证——服务端还认为你在蹲，
> 就会把你卡在缝口）。
