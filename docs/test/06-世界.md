# 6. 世界（World，6 个模块）

> 本册 6 个「方块交互」类模块：破坏（`Nuker`）、填充（`Flatten` / `LavaFiller`）、搭建（`AirPlace` / `BedCrafter`）、加载界面（`NoTerrainScreen`）。
> **GUI 里没有「世界」这一列** —— ClickGui 是 1.21.1 的 7 列原始布局，这 6 个分散在 `Misc`（`Nuker`/`LavaFiller`/`BedCrafter`/`NoTerrainScreen`）、
> `Player`（`AirPlace`）、`Movement`（`Flatten`）三列里，本册只是为了测试方便按功能归到一起（对照表见 `docs/TEST-PLAN-26.2.md`）。
>
> 源码同样分散在三处：`movement/Flatten.java`、`player/AirPlace.java`、`misc/`（其余四个）。
> 找模块时以 GUI 列 + 模块名为准，不看目录。

## 适用范围

| 模块 | 文件 | 干什么 |
|---|---|---|
| `AirPlace` | `player/AirPlace.java` | 对着空气放方块；同时给其它模块开"空中放置"总开关 |
| `BedCrafter` | `misc/BedCrafter.java` | 自动放工作台 → 开界面 → 从配方书连做床 |
| `Flatten` | `movement/Flatten.java` | 卡进方块后把脚下补成黑曜石 |
| `LavaFiller` | `misc/LavaFiller.java` | 把范围内的岩浆源用黑曜石封掉 |
| `NoTerrainScreen` | `misc/NoTerrainScreen.java` | 关掉「加载地形 / 进度」界面 |
| `Nuker` | `misc/Nuker.java` | 球形范围内自动挖掘（走 `PacketMine`） |

**不覆盖**：`PacketMine` 本身（玩家列）、`AutoWeb` / `Burrow` / `Surround`（战斗列）、`Scaffold`（移动列，它自己会放方块）。

**风险总览**：只有 `Nuker` 是高危（短时间大量破坏包，Grim 系必 setback），`AirPlace` / `Flatten` / `LavaFiller` 是中危
（都是发包放置，放不上会被服务端回弹），`BedCrafter` 低危，`NoTerrainScreen` 无风险。

## 测试场地建议

**创造模式 + 一片石头地**。世界类模块全都要"有东西可挖/可填/可放"，别在草地上测。

```mcfunction
# 进服后
/gamemode creative

# 1) 41×41、6 格厚的石头试验田（一次 /fill 铺完，别手搭）
#    站在平地中心、面朝 +X 执行；所有下面命令都相对你脚下
/fill ~-20 ~-6 ~-20 ~20 ~-1 ~20 minecraft:stone

# 2) 道具
/give @s minecraft:obsidian 512
/give @s minecraft:crafting_table 64
/give @s minecraft:white_wool 64
/give @s minecraft:oak_planks 64
/give @s minecraft:sand 128
/give @s minecraft:red_sand 64
/give @s minecraft:diamond_pickaxe

# 3) 分区别手贱挖坏，各模块场地互不重叠（+X 前、-X 后、+Z 右）
# A. 3×3 岩浆源池 —— LavaFiller（直接 /fill 成岩浆就是 9 个源方块，不用先挖坑）
/fill ~4 ~-1 ~-2 ~6 ~-1 ~0 minecraft:lava

# B. 沙堆 —— Nuker 的 Sand 模式（普通沙 + 红沙各一堆）
/fill ~-6 ~-1 ~4 ~-2 ~1 ~8 minecraft:sand
/fill ~-6 ~-1 ~-10 ~-2 ~1 ~-6 minecraft:red_sand

# C. 5×5 石墙 —— AirPlace（对着墙外的空气放方块，一眼能看到"凭空出现"）
/fill ~-2 ~ ~12 ~2 ~4 ~12 minecraft:stone

# D. 20 格高的悬空平台 —— Flatten / AirPlace 的"边缘卡方块"场地
/fill ~10 ~20 ~10 ~14 ~20 ~14 minecraft:stone

# E. 一个 2 格深的坑 —— 顺便验证 Nuker 的 Down 开关
/fill ~12 ~-2 ~-6 ~14 ~-1 ~-4 minecraft:air
```

**记录方式**：世界类模块的现象都在"方块"上，用 **F3 看坐标 + 数方块**，不要凭截图印象。
每次开模块前，先把 `/tp @s 0 ~ 0` 回到场地中心，避免上一轮的残留方块干扰判断。

**必须先确认的两件事**：

1. `AirPlace` 的 `Module` 开关影响**所有**放置模块（它会接管 `BlockUtil.getPlaceSide` / `allowAirPlace()`），
   测 `Flatten` / `LavaFiller` / `Scaffold` 时要么统一关掉它、要么在记录里写清状态。
2. 单机集成服会放过很多放置校验，`Nuker` / `AirPlace` 的"能不能放/能不能挖"必须**进服再验一次**。

## 建议顺序（低危 → 高危）

1. `NoTerrainScreen`（无风险，唯一一个只看画面的）
2. `BedCrafter`（全是正常交互包，但 GUI 流程长）
3. `LavaFiller`（只在岩浆上动作，失败也不伤人）
4. `AirPlace`（其它放置模块的地基，先测它）
5. `Flatten`（前置最刁钻，放在 `AirPlace` 之后便于对比）
6. `Nuker`（最后，破坏包最多，最容易被反作弊盯上）

## 模块测试

### NoTerrainScreen（没有加载界面）

| 关键设置 | 无设置项（只有公共的 `Key` / `Drawn`） |
| 步骤 | 1. 关模块，单人存档里反复进出（退出到标题再进），记下"加载地形"界面停留多久<br 2. 开模块，同样进出 → 加载界面应被立刻跳过，直接看到世界<br 3. 用 `/execute in the_nether run tp @s 0 70 0` 换维度，观察换维度时是否还出现进度界面<br 4. 进一个远程服务器（`S` 环境）重做 2：网络慢时应直接看到"世界还没长出来"而不是加载条<br 5. 关模块重进，确认加载界面回来了 |

| 结果 | [ ] ✅　[ ] ⚠️　[ ] ❌ |

### BedCrafter（自动制作床）
`misc/BedCrafter.java` · 环境：**S** · 风险：低

| 项 | 内容 |
|---|---|
| 前置 | 背包里有 **工作台物品**（`crafting_table`，没有就什么都不会发生）+ 羊毛 + 木板；至少 **1 个空槽**（`getEmptySlots()==0` 会直接关模块）；附近有能放工作台的地面 |
| 关键设置 | `Rotate`（默认 false）、`Range`（默认 5，0~8）、`Disable`（默认 true） |
| 步骤 | 1. 清空背包留 5 个空槽，给 64 白羊毛 + 64 橡木木板 + 1 工作台<br 2. 站在场地空地中心，开 `BedCrafter`<br 3. 观察：附近出现工作台 → 界面自动打开 → 配方书连点床 → 每个床一键移到背包 → 界面关闭<br 4. 等背包塞满（空槽 0）→ 模块应自己关闭（`Disable=true`）<br 5. `Range` 5→2：工作台应只放在 2 格内；把它挪远再测一次<br 6. `Rotate` 打开：放置/交互时应看到转身<br 7. 把工作台物品拿走，再开模块 → 应该什么都不做（也不该崩） |
| 预期 | 工作台被放下并自动打开，背包按「3 羊毛 + 3 木板 = 1 床」的配方被床填满；空槽为 0 时自动关闭 |
| 失败信号 | 放了工作台但界面不开 / 界面开了却没做出床（26.2 配方书 API 改动）/ 卡在打开的工作台界面里 / 日志出现 `NoSuchMethodError` / 床的颜色与羊毛不符 |
| 结果 | [ ] ✅　[ ] ⚠️　[ ] ❌ |

> 这是本册 26.2 改动最大的一处：配方书从 `RecipeEntry#getResult` 换成了 `RecipeDisplayEntry#resultItems(ContextMap)`，
> 点击从 `clickRecipe` 换成 `handlePlaceRecipe`。**判定只看一件事：背包里到底有没有床。**

### LavaFiller（自动填岩浆）
`misc/LavaFiller.java` · 环境：**S** · 风险：中

| 项 | 内容 |
|---|---|
| 前置 | 背包有**黑曜石**（`InventorySwap=true` 时任何背包格都行）；`Range` 内有**岩浆源**——只认 `LavaFluid.Source`，流动岩浆不会被填 |
| 关键设置 | `PlaceDelay`（默认 50 ms，0~500）、`InventorySwap`（true）、`Range`（默认 5，0~8，步长 0.1）、`BlocksPer`（默认 1，1~8）、`DetectMining`（false）、`UsingPause`（true）、`Rotate`（true）、`PacketPlace`（true） |
| 步骤 | 1. 用场地 A 的 3×3 岩浆池，站在 3 格外开模块<br 2. 岩浆源应逐格变成黑曜石（流动部分不动）<br 3. `BlocksPer` 1→4、`PlaceDelay` 50→0：填充明显加快，观察一 tick 最多几格<br 4. `Range` 5→2：站到 4 格外，应不再填<br 5. `Rotate` 关掉：放置时不再转身（对比头是不是在甩）<br 6. 把黑曜石丢光，再开模块 → 应该安静地什么都不做<br 7. 打开 `UsingPause`，边吃边开 → 吃东西时不填 |
| 预期 | 范围内的岩浆源被黑曜石替换；流动岩浆、已被水冲成黑曜石/圆石的位置不受影响 |
| 失败信号 | 完全不填（先看背包有没有黑曜石）/ 填了但立刻被岩浆重新覆盖（说明放置被判失败）/ 只填脚边那一格 / 方块"闪一下又没了"（服务端拒收） |
| 结果 | [ ] ✅　[ ] ⚠️　[ ] ❌ |

> 26.2 把 `FluidState#getFluid` 换成了 `getType`、`LavaFluid.Still` 换成了 `LavaFluid.Source`。
> 如果**只填流动岩浆、不填源方块**，或者反过来一格都不填，第一个怀疑对象就是这里。

### AirPlace（空气放置）
`player/AirPlace.java` · 环境：**S** · 风险：中

| 项 | 内容 |
|---|---|
| 前置 | 主手拿**方块**（`BlockItem`，不是工具）；准心对着**空气**（射线终点格是空气才会出框）；`Range` 上限 6，正好卡服务端 reach |
| 关键设置 | `Module`（默认 true，其它模块的"空中放置总开关"）、`GrimBypass`（默认 false，放置前换副手躲检测）、`Crosshair`（默认 true）→ `Range`（默认 5，0~6）/ `Fill`（带开关）/ `AABB`（带开关） |
| 步骤 | 1. 手拿黑曜石，准心指 3 格外的空中 → 应立刻出现红色半透明框<br 2. 按住右键 → 框里出现黑曜石（悬空）<br 3. `Range` 5→6 → 更远处也能出框；再调到 1 → 只有贴脸才出框<br 4. 把 `Crosshair` 关掉 → 红框消失，此时只能靠别的模块调用它（见步骤 5）<br 5. 保持 `Module=true`、`Crosshair=false`，开 `Scaffold` 或 `Flatten`：它们的放置应改走空气放置路径<br 6. 把 `Module` 关掉，重做 5 → 应该恢复"必须贴着一个面才能放"<br 7. `GrimBypass` 打开，放一个方块：F3+L 或 `PacketLogger` 应看到先 `SWAP_ITEM_WITH_OFFHAND`、放完再换回来 |
| 预期 | 3~6 格外凭空出现方块；红框跟随准心且只在目标是空气时显示；`Module` 关闭后其它模块不再走空气放置 |
| 失败信号 | 按右键没反应 / 方块只出现在手边（没走 airPlace 路径）/ 框出现了但放不上（服务端回弹，距离超了）/ 开 `GrimBypass` 后副手物品丢失或不换回来 |
| 结果 | [ ] ✅　[ ] ⚠️　[ ] ❌ |

> `Range` 最大就是 6：这不是随便定的，是服务端对 `useItemOn` 的距离校验上限。调到 6 还不生效就是服务端不接受。
> 另外注意 `Crosshair` 和 `Module` 是**两个不同用途的开关**——关掉 `Crosshair` 只关"准心红框 + 右键放置"，
> 其它模块照样能用 airPlace。

### Flatten（填平脚下）
`movement/Flatten.java` · 环境：**S** · 风险：中

| 项 | 内容 |
|---|---|
| 前置 | **三个条件同时满足**才动作：① `isInsideBlock()`（身体和固体方块重叠）② `onGround()` ③ 脚下 4 个格（±0.5）是**可替换方块**（空气/水）。标准用法：先用 `VClip` 的 `Glitch` 模式（或漏洞列的 phasing）把自己卡进方块，**再**开它。另外把 `AirPlace` 的 `Module` 打开——否则 `getPlaceSide` 找不到可点击面，同样不动作 |
| 关键设置 | `Rotate`（true）、`DetectMining`（true）、`InventorySwap`（true）、`UsingPause`（true）、`Cover`（false）、`BlocksPer`（默认 2，1~8）、`Delay`（默认 100 ms，0~1000） |
| 步骤 | 1. 先打开 `AirPlace` 的 `Module`（`Crosshair` 关掉也无所谓）<br 2. 站到场地 D 的悬空平台上，用 `VClip`（`Mode=Glitch`）把自己卡进平台方块里<br 3. 立刻开 `Flatten`，看脚下 4 个位置是否变成黑曜石<br 4. `BlocksPer` 2→8、`Delay` 100→0：一次填的格数与频率明显上升<br 5. `Cover` 打开：只填"头顶是实心"的位置（悬空处不再填）<br 6. `DetectMining` 保持开，让队友挖你脚下那块 → 正在被挖的位置不填<br 7. 站在纯实心地面（脚下就是地面方块）开模块 → 应该**不动作**（目标不可替换，属正确行为） |
| 预期 | 卡进方块后脚下 4 格被黑曜石补上；约每 `Delay` 一批，每批 ≤ `BlocksPer` 格 |
| 失败信号 | 开了完全没反应（**先查前置**：是不是真在方块里、脚下是不是实心）/ 只填 1 格就停 / 把自己封死在黑曜石里出不来（`VClip` 再穿出来）/ 掉落伤害没被挡住 |
| 结果 | [ ] ✅　[ ] ⚠️　[ ] ❌ |

> 这个模块的「开了没反应」大概率不是 bug，而是**前置没满足**：它要求目标格可替换（`canBeReplaced`）。
> 所以第 7 步那个"不动作"是**正确答案**，别记成失败。真正要盯的是第 2~3 步：卡进方块的那一瞬间能不能补上。

### Nuker（范围挖掘）
`misc/Nuker.java` · 环境：**S** · 风险：高

| 项 | 内容 |
|---|---|
| 前置 | 周围有可挖方块；不开 `Sand` 时走 `PacketMine`，与 `PacketMine` 自己正在挖的位置互斥（它一旦有目标就 return）；`getClickSideStrict` 要求有可点击面 |
| 关键设置 | `Range`（默认 4，0~8，步长 0.1）、`Down`（false）、`Sand`（false）→ `Breaks`（默认 10，0~20，**只在 `Sand` 打开时出现**） |
| 步骤 | 1. 站在石头地中央开模块 → 周围方块被逐个挖掉，掉落物进背包<br 2. `Range` 4→8：破坏半径明显变大，同时看帧数与包量<br 3. `Down` 打开：脚下的方块也开始被挖（关掉时不挖脚下方块，这是安全设计）<br 4. `Sand` 打开：只挖沙子/红沙，一次最多 `Breaks` 个（场地 B 的两堆沙）<br 5. `Sand` 关掉，在沙堆旁重测 → 应回到"什么都挖"<br 6. 挖到基岩/黑曜石（`PacketMine.unbreakable`）→ 应跳过，不卡住<br 7. 在 Grim/NCP 服上重做 1，记录几秒后被 setback / 踢 |
| 预期 | 以你眼睛为中心的球形范围内逐块破坏，掉落物正常；`Down=false` 不挖脚下，`Sand=true` 只挖沙 |
| 失败信号 | 挖两下就停（和 `PacketMine` 抢目标）/ 只往一个方向挖 / 方块反复"挖了又回来"（服务端不认）/ 被踢或瞬间掉帧 |
| 结果 | [ ] ✅　[ ] ⚠️　[ ] ❌ |

> `Down` 默认是 `false`：脚下方块不挖。测的时候别一上来就把它打开——自己掉进洞里会干扰后面的判定。
> `Breaks` 这个滑块**只有 `Sand` 打开才显示**，在 GUI 里找不到不是 bug。

## 本册回归优先级（20 分钟版）

只有 6 个模块，`NoTerrainScreen` 30 秒就能看出来，`LavaFiller` 需要备岩浆。
时间紧时按这 4 个跑（约 20 分钟）：

| 顺序 | 模块 | 时长 | 只测这一件事 |
|---|---|---:|---|
| 1 | `AirPlace` | 4 min | 手拿方块对空 4 格右键 → 凭空出现方块；再关 `Module` 确认其它模块恢复"必须贴面" |
| 2 | `BedCrafter` | 6 min | 给羊毛+木板+工作台 → **背包里到底有没有出现床**（26.2 配方书重写，最容易静默失效） |
| 3 | `Flatten` | 5 min | `VClip` Glitch 卡进方块 → 脚下 4 格变黑曜石 |
| 4 | `Nuker` | 5 min | `Range=4` 挖 10 秒，方块真的被破坏、掉落物进包、没被踢 |

> `NoTerrainScreen` 和 `LavaFiller` 放最后顺手过：前者进出存档两次就知道；后者只要背包有黑曜石、
> 场地 A 的岩浆池还在，开模块看岩浆有没有变黑曜石即可。
