# 7. 漏洞（Exploit，18 个模块）

> 本册只管 `src/main/java/dev/luminous/mod/modules/impl/exploit/` 下的 18 个模块。
> 环境准备、记录规范在 [00-环境与工具](00-环境与工具.md)，这里不重复 —— 但**这一册的环境要求比其它册严**，先看 7.1。

## 7.1 风险分级（必读，这一册最容易搞坏东西）

| 级别 | 模块 | 会搞坏什么 | 只在哪测 |
|---|---|---|---|
| 🟥 **只在自己的测试服玩** | `ServerLagger` | 把服务端主线程打满：整服 TPS 归零、卡到没人能动、极端情况崩档。在公共服上用它不是"测试"，是**打服**，会被封、可能被追责 | 你能随时 `Ctrl+C` / 杀进程 / 重启的服，或者干脆单机 |
| 🟧 **会被服务端反作弊记录** | `Phase` `Clip` `Blink` `PingSpoof` `BowBomb` `InfiniteTrident` `XCarry` | 进 NCP/Matrix/Vulcan/Grim 日志，被 setback、踢、封号；其中 `Phase`/`Clip` 还可能把你塞进方块里出不来、掉虚空 | 先在自己的关反作弊服验功能，再上公共服只验"会不会立刻被拦" |
| 🟨 **基本无害** | `AntiHunger` `ChunkESP` `TeleportLogger` `SkinFlicker` `NoResourcePack` | 最坏是被踢一次、画面出错、需要重进 | L 或 S 都行 |

上面没点名的 5 个（`AntiPacket`、`ChorusControl`、`MaceSpoof`、`PacketControl`、`RocketExtend`）**都在改发包或容器状态，一律按 🟧 对待**，别当无害模块随手开着逛街。

三条铁律，照做：

1. **不要在任何不归你管的服上测 🟥**。`ServerLagger` 的 `Selector` / `Window` / `OutOfBounds` / `InteractBlock` / `AAC` 这几个模式尤其别手滑 —— 它们的设计目的就是让服务端算不动。
2. 🟧 的"功能是否真生效"只在**关反作弊的自己的服**上验；公共服只验"会不会立刻被拦"。两个结果别混着看：被 setback 不等于模块坏了，模块真坏了也可能在公共服上"看起来没事"。
3. 每个 🟧 开测前：`/tp` 记一次坐标、`/gamerule keepInventory true`、把背包截图备份。**卡进方块、幽灵物品、掉虚空**，在本册是常态而不是意外。

## 7.2 测试环境与场地

全部模块标 **S**（唯一例外 `SkinFlicker` 用 L 就够）：判据和服务端完全相关 —— 服务端有没有接受那个包、有没有把你拉回、容器内容两边对不对得上。单机（集成服）里大量非法操作被直接放过，"单机通过"在这册毫无意义。

**一次性准备**

```mcfunction
/gamemode survival                        # AntiPacket 的 S2CInventory 在创造模式整段不生效
/gamerule keepInventory true              # 防止测崩溃类时真掉装备
/tp ~ ~ ~                                 # 每节开测前手动记一次坐标

/give @s minecraft:ender_pearl 64         # Phase
/give @s minecraft:chorus_fruit 64        # ChorusControl / TeleportLogger
/give @s minecraft:bow
/give @s minecraft:arrow 64               # BowBomb
/give @s minecraft:trident 8              # InfiniteTrident
/give @s minecraft:mace                   # MaceSpoof
/give @s minecraft:elytra
/give @s minecraft:firework_rocket 64     # RocketExtend
/give @s minecraft:scaffolding 64
/give @s minecraft:obsidian 64            # Clip 的 Obsidian / Phase 的 Break
```

**场地**（一次搭好，后面每节都用）

```mcfunction
# A. 一格厚石墙 —— Clip / Phase 的主场地，贴着它站
/fill ~2 ~ ~-3 ~2 ~4 ~3 minecraft:stone

# B. 三格厚石墙 —— 对照：穿不过去才是正常
/fill ~6 ~ ~-3 ~8 ~4 ~3 minecraft:stone

# C. 基岩台 —— Clip 的 NoPacket 模式要求包围盒真的和基岩相交
/fill ~-4 ~-1 ~-4 ~0 ~-1 ~0 minecraft:bedrock

# D. 25 格高平台 —— MaceSpoof 的对照伤害 / RocketExtend 的起跳点
/fill ~-2 ~25 ~10 ~2 ~25 ~14 minecraft:stone

# E. 一间放箱子的屋子 —— ServerLagger 的 Song、AntiPacket、XCarry、InfiniteTrident 共用
/setblock ~-8 ~ ~-8 minecraft:chest
```

**`NoResourcePack` 需要服务端配合**（只在本地测）

```properties
# 自己的测试服 server.properties
resource-pack=http://127.0.0.1:8080/test.zip
require-resource-pack=true
```

改完重启服。没有这一项，`NoResourcePack` 完全无法验证 —— 它不是客户端能自己演出来的模块。

## 7.3 建议测试顺序

从"最不可能把东西弄坏"排到"会打崩服务端"：

| # | 模块 | 风险 | 说明 |

| 5 | `NoResourcePack` | 🟨 | 只回资源包状态包 |
| 6 | `ChorusControl` | 🟧 | 扣住位置包，容易把自己定身 |
| 7 | `AntiPacket` | 🟧 | 容器状态不同步，最容易出幽灵物品 |

| 12 | `MaceSpoof` | 🟧 | 假位移包骗伤害 |
| 13 | `BowBomb` | 🟧 | 一次触发上百个移动包，公共服一眼恶意 |

## 7.4 逐模块测试

### AntiHunger（防掉饱食度）
`exploit/AntiHunger.java` · 环境：**S** · 风险：**🟨 基本无害**

| 项 | 内容 |
|---|---|
| 前置 | 生存模式、饱食度吃满、站在平地上；手里空着（别拿食物） |
| 关键设置 | `Sprint`（默认**关**，取消 `START_SPRINTING` 包，服务端认为你没疾跑）、`Ground`（默认**开**，把移动包的 `onGround` 一直改成 false） |
| 步骤 | 1. 关模块，按住 W + 间歇小跳 30 秒，记饱食度掉了几格（基准）<br>2. 开模块，同时打开 `Sprint`，同样跑 30 秒，比较饱食度<br>3. 只留 `Ground`（`Sprint` 关），原地站着慢慢走 30 秒，看饥饿条是否不动<br>4. 两个都开，连续跳跃移动 30 秒（跳跃是最耗饱食度的动作，最能看出差别）<br>5. 吃一个金胡萝卜，看饱食度条是否正常回升（只测"掉"，别把"回"也抑制了） |
| 预期 | 客户端速度、疾跑 FOV、跳跃高度全部正常；服务端的饱食度下降明显变慢，`Ground` 单独开时几乎不动；吃东西仍能回饱食度 |
| 失败信号 | 饱食度照掉（`Phase` 开着时本模块整个 `return`，源码硬条件；`BowBomb` 触发的瞬间也会 `return`）；被踢 `Flying is not enabled on this server`（`Ground` 一直报离地，而服没开 `allow-flight=true`）；人走不动/被 setback（服务端认为你没疾跑，却收到疾跑速度的位移）；饱食度不掉了但你也跳不起来 |
| 结果 | [ ] ✅　[ ] ⚠️　[ ] ❌ |

### ChunkESP（区块显示）
`exploit/ChunkESP.java` · 环境：**S** · 风险：**🟨 基本无害**

| 项 | 内容 |
|---|---|
| 前置 | 进一个**会正常发区块包**的服（自己的 26.2 Fabric 服即可）；`/tp` 到没去过的远处，让服务端必须现发区块 |
| 关键设置 | `DetectMode`（默认 `Normal`，另有 `IgnoreBlockExploit` / `BlockExploitMode`）、`Chunks-Distance`（默认 128，单位是区块）、`RenderHeight`（默认 0，框画在这个 Y 平面上）、`PaletteExploit`（默认开，靠调色板判新旧）、`BeingUpdated`（默认开）、`OverworldOldChunks` / `NetherOldChunks` / `EndOldChunks`（默认全开）、`LiquidExploit`（默认关）、`blockUpdateExploit`（默认关）、`WorldLeaveRemove`（默认开）、`RemoveRenderDist`（默认关）、颜色：`New`（红）/ `Old`（绿）/ `BeingUpdated`（绿）/ `OldVersion`（黄绿）/ `BlockExploit`（蓝） |
| 步骤 | 1. **刚进服务器的头 3~5 秒**盯着屏幕：新区块该立刻出现红框（`New`），这是 26.2 改过加载判断后的第一验收点<br>2. `/tp` 到 5000 格外，看新发来的区块是否继续标红、旧框是否跟着消失<br>3. 走进已生成过的老区域，看是否标绿（`OldVersion`/`Old`）<br>4. 换维度（走下界门再回来），检查旧框是否残留、新维度的区块是否照常判<br>5. 打开 `blockUpdateExploit`，把 `DetectMode` 切到 `BlockExploitMode`，在旁边放/挖一个方块，看该区块是否变蓝（`BlockExploit`）<br>6. `RenderHeight` 从 0 调到 100，框应整体升高；`Chunks-Distance` 从 128 调到 32，远处框应消失 |
| 预期 | 新区块红框、旧区块绿框，进服几秒内就开始画；换维度后新维度的区块照常判定；改 `RenderHeight` / `Chunks-Distance` 立刻体现在画面上 |
| 失败信号 | 进服后一直没有任何框 —— 先调 `RenderHeight`（默认 0，你在地下/建筑里可能根本看不到那个平面），再把 `Chunks-Distance` 调大；某个区块怎么都不出框（源码只在"本地还没有这个区块"时才做判定，`getChunkNow` 非空就整段跳过）；**换维度后旧框画在新维度同一坐标上**（五个集合都只存 `ChunkPos`、不带维度，所以主世界 x=0/z=0 的框会出现在下界同一坐标，且那个坐标的新区块因为"已存在"不再被判定 —— 26.2 删掉加载界面分支后没人清，记 ⚠️）；`DetectMode` 三个档切来切去没区别（`blockUpdateExploit` 默认关，三个模式全退化到同一分支）；走远后框不消失（`RemoveRenderDist` 默认关） |
| 结果 | [ ] ✅　[ ] ⚠️　[ ] ❌ |

> **26.2 改动点**：进服/换维度时"加载界面"的判断被改掉了 —— `DownloadingTerrainScreen` 在 26.2 已移除，原来的重置分支整段删除，现在只有 `OpenScreenEvent`（断连界面）和 `GameLeftEvent` 两处清数据。所以"刚进服务器那几秒"和"换维度之后"是本模块唯二没人验证过的区间，第 1、4 步必须单独看，别只测"在服里待着会不会画框"。

### TeleportLogger（传送检测）
`exploit/TeleportLogger.java` · 环境：**S** · 风险：**🟨 基本无害**

| 项 | 内容 |
|---|---|
| 前置 | 第二个客户端（`Tester2`）进同一个服，站你 50 格外；想测紫颂果的话让他背包里有紫颂果 |
| 关键设置 | `Teleport`（默认**关** —— 不开它整个传送检测都不工作）、`Delay`（默认 1s，采样间隔）、`Distance`（默认 20m，位移阈值）、`Message`（默认开，聊天栏报点）、`Chorus`（默认关，靠 `CHORUS_FRUIT_TELEPORT` 音效抓紫颂果落点）、`MaxTime`（默认 10s，只作用于 `Chorus` 的框）、`AABB` / `Fill` / `Text` / `ChamsFill` / `ChamsLine`（五个颜色项，每个自带开关，默认全开） |
| 步骤 | 1. 先把 `Teleport` 打开（默认是关的），`Distance` 保持 20、`Delay` 1s<br>2. 让 `Tester2` `/tp` 到 50 格外，聊天栏应出现 `Tester2 Teleported to x, y, z.`，他原来的位置留下半透明残影<br>3. 让他在 20 格内小范围走动，确认不报警；再把 `Distance` 调到 3，让他走两步，应该每次都报<br>4. `Chorus` 打开、`MaxTime` 10：让他吃紫颂果传走，落点应出现一个框 + `Chorus` 文字<br>5. 把 `AABB` / `Fill` / `Text` 三个开关各关一次，确认对应元素逐个消失<br>6. `Message` 关掉，确认只剩画面不刷聊天栏 |
| 预期 | 超过 `Distance` 的位移被报点并留残影；紫颂果落点画框；五个颜色开关各自管自己那部分 |
| 失败信号 | 完全没反应（九成是 `Teleport` 还关着 —— 它默认关）；小传送不报（`Distance` 20 太大，或 `Delay` 1s 采样正好跨过了动作）；紫颂果不显示（`Chorus` 关着，或服务端没播那个音效、被资源包替换了音效）；残影永远不消失（`Teleport` 的残影没有过期清理，只在你重进服/重新开关模块时清空，这是设计不是 bug）；`Teleport` 关掉后 `Delay` / `Distance` 两个滑块会隐藏 |
| 结果 | [ ] ✅　[ ] ⚠️　[ ] ❌ |

### SkinFlicker（皮肤闪烁）
`exploit/SkinFlicker.java` · 环境：**L** · 风险：**🟨 基本无害**

| 项 | 内容 |
|---|---|
| 前置 | 单机即可；F5 切第三人称，或让第二个客户端看你；**换一个带披风/外套的皮肤**，默认皮肤没有披风层，看不出效果 |
| 关键设置 | `Mode`（默认 `Random`，另有 `Switch` / `Sync`）、`CAPE`（默认开）、`JACKET`（默认开）、`LEFT_SLEEVE`（默认开）、`RIGHT_SLEEVE`（默认开）、`LEFT_PANTS_LEG`（默认开）、`RIGHT_PANTS_LEG`（默认开）、`HAT`（默认开） |
| 步骤 | 1. 开模块，`Mode=Random`，看各部件每 tick 随机闪<br>2. `Mode=Switch`，看是否整体反转（显示变隐藏）<br>3. `Mode=Sync`，看是否所有部件整齐地一起开/关<br>4. 只关掉 `HAT`，确认帽子层停止闪烁，其它层照闪<br>5. 关模块，再看自己 —— **部件会停在最后的开关状态，不会自动还原** |

| 结果 | [ ] ✅　[ ] ⚠️　[ ] ❌ |

### NoResourcePack（反资源包）
`exploit/NoResourcePack.java` · 环境：**S** · 风险：**🟨 基本无害**

| 项 | 内容 |
|---|---|
| 前置 | 自己的服已按 7.2 配好 `resource-pack` + `require-resource-pack=true`，重启完成；客户端资源包目录清干净（避免"其实本地已有缓存"） |
| 关键设置 | **无**（模块没有设置项，开关即生效） |
| 步骤 | 1. 先**关着**模块进服，确认基线行为：要么弹下载确认框，要么（`require-resource-pack=true`）被拒绝/踢<br>2. 开模块再进服：不应弹任何下载提示、不应卡加载界面，直接进到游戏<br>3. 进服后等 3 秒（`SUCCESSFULLY_LOADED` 在 40 tick 后才补发），确认没有被服务端二次踢出<br>4. 让服端换个资源包地址（改 `server.properties` 重启），再进一次 —— `packId` 必须跟着新包变，仍能进<br>5. 关模块立刻重进，确认行为回到第 1 步 |
| 预期 | 不下载、不弹窗、不卡界面，但服务端认为你已经成功加载（不会被 `require-resource-pack` 踢） |
| 失败信号 | 仍然弹下载确认（包没被拦下）；被踢 `You must accept the resource pack`（伪造的 `ACCEPTED` 用的 id 不对 —— 26.2 是回显 `packet.id()`，服换包地址后理论上会自动跟，实机要验第 4 步）；卡在"正在加载资源包/连接中"（拦了推送但没补发 `ACCEPTED`，注意它是 15 tick 后才发，前 0.75 秒本来就是空的）；进服几秒后掉线（`SUCCESSFULLY_LOADED` 没发出去） |
| 结果 | [ ] ✅　[ ] ⚠️　[ ] ❌ |

### ChorusControl（紫颂果控制）
`exploit/ChorusControl.java` · 环境：**S** · 风险：**🟧 会改发包/状态（补充归类）**

| 项 | 内容 |
|---|---|
| 前置 | 主手拿紫颂果；站平地、远离岩浆和虚空（紫颂果本来就爱把你扔到危险位置）；先去设置里给 `Confirm` 绑一个顺手键（默认 -1 = 没绑，不绑就只能靠关模块来落地） |
| 关键设置 | `Confirm`（默认 -1，按下才接受这次传送）、`Color`（默认半透明白，落点框的颜色） |

> `ServerLagger` 在 `Mode` 下拉里一共 28 项：`AAC` `AAC2` `Armor` `Boat` `Console` `Chunk` `Crafting` `Essentials` `FaweWorldEdit` `InteractBlock` `InteractItem` `InteractNoCom` `InteractOOB` `InvalidClickSlot` `Lectern` `MovementSpam` `MultiverseCore` `NullPosition` `OutOfBounds` `Offhand` `Promote` `Selector` `Song` `Swap` `SwitchSlot` `Vehicle` `Window` `WorldEdit`。**默认值 `Selector` 本身就是最狠的载荷之一**（把 2032 个 `[` 塞进 `msg @a[nbt={...}]` 的命令补全里，逼服务端解析畸形 NBT），好在一轮就会自己关；真正危险的是关掉 `SmartDisable`，或者换到 `Window` / `OutOfBounds` 这种**没有自动关闭**的模式 —— 第一次测请先把 `Mode` 改成 `Console`。

## 7.5 本册回归优先级

**只有 20 分钟，按这个顺序测这 4 个，能覆盖本册 80% 的风险：**

| 顺序 | 模块 | 分钟 | 为什么是它 |
|---:|---|---:|---|
| 1 | `ChunkESP` | 4 | 26.2 删掉了加载界面的判定分支，进服/换维度这几秒完全没验过。只测两项：「刚进服头 3~5 秒有没有红框」「换维度后旧框有没有残留」。抓的是加载判断回归。 |
| 2 | `AntiHunger` | 4 | 最便宜的发包类验证点。开着 `Ground` 跑 30 秒看饱食度掉不掉，一次就能确认"改 `onGround` 的移动包"这条链路还通，顺便确认会不会被踢 `Flying is not enabled`。 |
| 3 | `AntiPacket` | 8 | 容器状态的总闸，也是本版改动最大的模块（`ClickSlotC2SPacket` 变 record）。只测两条：「生存模式连点容器后停手 2 秒，`AutoSync` 有没有把槽位纠回」「关掉模块重开容器，物品数量对不对得上」。抓的是新建包构造与重同步。 |
| 4 | `Blink` | 4 | 覆盖「扣包 → 一次性补发 → 拉回检测」整条状态机，是 `Clip` / `Phase` / `PacketControl` 的共同底座。只测两项：「关模块时有没有真的瞬移」「`LagbackCheck` 收到位置包会不会自动放弃」。 |

**为什么是这 4 个**：`ChunkESP` 抓 26.2 唯一被删掉的判定分支（加载界面），`AntiHunger` 抓移动包的基本改写（`isDestroying` / `Action` 枚举），`AntiPacket` 抓 26.2 改得最狠的那个包（不可变 record），`Blink` 抓整条"扣包再补发"的状态机。剩下 14 个的失败模式基本是这 4 个的子集 —— 真正独有的只剩 `ServerLagger`（**不在这 20 分钟里，也永远别在别人的服上补**）和 `NoResourcePack`（要改服务端配置，单独安排）。

**还剩 5 分钟的话**，按顺序补：`Clip`（站桩推墙，唯一测"位置包抖动推进"的）→ `RocketExtend`（唯一需要看"爆炸而不是消失"的）→ `MaceSpoof`（唯一测"假位移换伤害"的）。
